# Архитектурные решения

## Бизнес

Главной бизнес задачей системы является возможность оперативного моделирования финансовой и товарной ситуации в ходе тактического планирования исполнительным советом.

Реализуется данная задача через предоставление руководителям отделений возможности планирования показателей и отражения фактических результатов с учетом специфики их отделений.
Ключевыми характеристиками деятельности каждого отделения являются данные о движении денег и движении товара.

Система реализует независимые закрытые сервисы для операционной и тактической деятельности руководителей.

Способ разделения системы на закрытые контуры производится по слою отделений в [оргструктуре](https://drive.google.com/file/d/1vsX_JCW9MaWJ1zjqBHmlnbgNDwXOtbDh/view?usp=sharing) компании.

## Описание технического стека системы

- БД - MongoDB
- Backend - PostgreSQL
- Frontend - React 18, Typescript
- Организация Frontend приложений - Turborepo
- Сборка, сплитинг, минификация - Webpack
- Хранилище и доставка - Git и GitHub Actions
- Железо - арендованный VPS
- Среда - Docker
- ОС - Ubuntu 24.04.1 LTS

---

## Почему Frontend монорепозиторий?

- Система имеет большое количество общих бизнес сущностей и правил. Каждый сервис является отражением работы структурного отделения, который наследует правила работы организации в целом. Монорепозиторий позволит наследовать данные сущности и правила во всех сервисах, что ускоряет и упрощает разработку.
- Простая организация общих модулей, которые используются во всех сервисах.
- Возможность организации единого api пакета.
- Система не подразумевает большого штата разработчиков, независимость команд и их релизов не критична.
- Удобство внедрения, контроля и использования конфигурационных правил (линтинг, typescript, webpack, тесты, стили, ui, типы)
- Упрощенный контроль зависимостей.
- Удобство рефакторинга.

---

## Почему Webpack?

- Возможность тонкой настройки сборки, либо организации Module Federation в случае необходимости. На сегодняшний день монорепозиторий кажется достаточным решением, но развитие компании может привести к интенсивному развитию разработки. В таком случае может потребоваться быстро организовать полирепозиторий и возможно микрофронтенд архитектуру.

---

## Почему React?

- React - даже при спорной производительности и корявости архитектуры даёт самое главное - масштабируемый коммерческий продукт. При этом тестировать Vue/Solid ценой бизнеса дорого.
- Достаточно большой рынок React разработчиков
- Достаточно большой объём готовых React решений

## DevOps инфраструктура

- Требование минимизировать расходы на доставку кода
- GitHub Action - бесплатно. GitLab - недоступен в РФ. Проблема в лимитах ранеров.
- Поэтому сделан собственный ранер на сервере с возможностью выбора при деплое в интерфейсе GitHub Actions
- Деплой в Docker контейнер
- Nginx для распределения запросов
- VPS сервер
